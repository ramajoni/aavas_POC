# Release 0.6.3 (2026-11-19)

Previous release: 0.6.2. A patch release that makes the server installable from the
repository alone. Pricing, the API and the data are unchanged.

## Highlights

- **A clean install now starts.** Building the environment from `requirements.txt`
  alone used to leave out `python-multipart`, and the API refused to start. Preparing
  the AWS deployment in a fresh environment on the server exposed it.
- **What the server runs with is written down.** `requirements-optional.txt` lists the
  optional packages the live server has used: SHAP, xgboost, lightgbm, catboost and
  the Anthropic SDK.

## Changes

### Fixed
- `requirements.txt` lacked `python-multipart`, which FastAPI needs for the borrower
  document uploads: an environment built from the requirements alone could not start
  the API. Found by running the test suite in a clean environment on the server.

### Added
- `requirements-optional.txt`: the optional packages the deployed server runs with
  (shap, xgboost, lightgbm, catboost, anthropic). They were installed by hand on the
  server and recorded nowhere, so a rebuild from the requirements would have dropped the
  AI explanation, SHAP attributions and three learner families without an error.

## Upgrade steps

1. Build or refresh the server environment from both files:
   `pip install -r requirements.txt -r requirements-optional.txt`.
2. Development machines need only `requirements.txt`; the optional packages are
   detected at run time, and the platform falls back without them.

## Known issues

- The OmniXAI explainability reports are generated outside the server environment
  (`scripts/setup_xai_env.sh`, then `scripts/run_omnixai.py`); a server that has not
  generated them shows no reports on the Model Explainability page.
- Everything listed under Known issues in 0.6.2 still stands.
