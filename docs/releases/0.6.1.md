# Release 0.6.1 (2026-11-19)

Previous release: 0.6.0. A patch release. It changes nothing in pricing, the API or the
data.

## Highlights

- **The optional packages are installed and working.** shap, xgboost, lightgbm,
  catboost and anthropic are in the main environment; omnixai is in its overlay
  environment, `.venv-xai`.
- **The OmniXAI reports are generated again** for all six models (stage1, stage2,
  conversion, prepayment, risk, override), including the counterfactuals. Before this
  they failed under pandas 3.
- **The test suite:** 1017 passed, 3 failed, 2 skipped. In 0.6.0 it was 969 passed and
  31 failed. The 3 remaining failures wait on the Stage-1 decision.

## Changes

### Changed
- `scripts/setup_xai_env.sh` builds the OmniXAI overlay on Windows (Git Bash) as well, and
  inherits the repo's own training environment (`.venv`) through a `.pth` file when it
  exists, so the explained models load in exactly the packages they were trained in.
  On Windows it installs `chroma-hnswlib` (the same library, prebuilt) in place of
  `hnswlib`, which has no Windows wheel and needs the MSVC build tools.
- `requirements-xai.txt` pins `setuptools<81`: omnixai imports `pkg_resources`, which
  setuptools 81 removed.

### Fixed
- The OmniXAI analysis failed on every model under pandas 3: omnixai 1.3.1's ALE wrote
  fractions into integer tables, and its imbalance analysis wrote into a read-only
  array. Both methods are replaced at run time with the one-line fix
  (`_patch_omnixai_for_pandas3` in `src/aavas/xai/omnixai_analysis.py`).
- Two explainability tests depended on local artefacts: one named the risk model's
  rank-agreement score from an earlier training run, the other a dashboard screenshot
  taken by hand. They now check the trust thresholds and every model's reading
  against them, and serve a capture the test places itself.

## Upgrade steps

1. Optional packages in the main environment:
   `pip install "shap>=0.46" "xgboost>=2.0" "lightgbm>=4.0" "catboost>=1.2" "anthropic>=1.0"`.
   They are the `full`, `learners` and `llm` extras in pyproject.toml. Without them the
   platform falls back (ablation instead of SHAP, scikit-learn learners only, no
   AI-written explanation), and the tests that need them fail.
2. OmniXAI:
   1. Build the overlay: `bash scripts/setup_xai_env.sh` (Git Bash on Windows).
   2. Generate the reports: `PYTHONPATH=src .venv-xai/Scripts/python.exe scripts/run_omnixai.py --no-ui`
      (on Linux and macOS the interpreter is `.venv-xai/bin/python`).
   3. Never install omnixai into the main environment. Its pins (old dash, Flask,
      numpy and scikit-learn) would break the API and the trained models.
3. The anthropic SDK brings `httpx2`, which the FastAPI test client now prefers over
   `httpx`.

## Known issues

- **Stage-1 quote below the policy floor.** Three tests fail on it: the band covers the
  final price 56.8% of the time, and for some files the quote sits below the file's own
  policy floor. They wait on the Stage-1 band decision.
- **Dashboard screenshots** on the Model Explainability page are taken by hand from the
  running dashboards (`make xai`); none exist on this machine yet.
- **omnixai 1.3.1 is old.** It predates pandas 3 and numpy 2, and its pinned
  requirements conflict with this stack. It runs here through `--no-deps` and two
  run-time fixes; a newer omnixai, or replacing it, would remove both.
- Everything else listed under Known issues in 0.6.0 still stands.
