# Release 0.9.2 (2026-11-21)

Previous release: 0.9.1. A patch release of the demo data tool. The application, the
policy (HL-LAP-POLICY-2026.14) and the models are unchanged.

## Highlights

- **No demo ask below 13% any more.** Two of the 0.9.1 extended cases asked for 12.75% and
  12.70%. The policy allows no rate below 13% (`card_rate_floor`), and the 0.9.1 notes
  wrongly said every ask was inside the band. The two cases are rebuilt:

  | # | Customer, city | Decision it shows | Grade | Tenure | Card | Floor | Rec | Ask |
  |---|---|---|---|---|---|---|---|---|
  | E1 | Neha Kulkarni, Nashik | Axis letter 12.80% is under our floor; the best we can do is the floor | B | 4y | 15.00 | 14.40 | 14.40 | 14.15 |
  | E2 | Sandeep Joshi, Rajkot | ICICI letter 13.90% equals our rate: nothing to give | A | 7y | 14.50 | 13.90 | 13.92 | 13.62 |

- **The script now refuses an out-of-band ask.** Before a rate request is sent,
  `demo_scenarios.py` checks the ask against the policy band (13.00-17.00%) and stops,
  naming the scenario, if it falls outside.
- **Why the A+ short-tenure case is gone.** An A+ file of up to 60 months has a card rate
  of 13.00%, which is also its floor. The RM may only ask more than 25 bps under the
  recommendation, so no ask inside 13-17% exists for it: such a file never reaches the area
  manager.

## Changes

### Fixed
- Two extended demo cases asked for rates below 13%, which the policy forbids
  (`card_rate_floor`: no concession below 13%): E1 asked 12.75% and E2 12.70%. Both were A+
  files recommended at exactly 13.00%, where no valid ask can exist (the RM may only ask more
  than 25 bps under the recommendation). E1 is now a grade-B four-year file (ask 14.15%) and E2
  a grade-A seven-year file (ask 13.62%); they keep their tenure bands and the decision each
  shows. The 0.9.1 notes said every ask was inside the band; that was wrong for these two.

### Added
- `scripts/demo_scenarios.py` refuses any ask outside the policy band (`card_rate_floor` to
  `card_rate_ceiling`, 13.00-17.00%) before it is sent, naming the scenario.

## Upgrade steps

Nothing to deploy: the running application is unchanged. A server that ran the 0.9.1
extended set holds E1 and E2 with asks under 13%; remove those two files (back up the store
first) and add the rebuilt ones. A server that has not run it yet:

    python scripts/demo_scenarios.py --base http://127.0.0.1:8000 --set extended

## Known issues

- Everything listed under Known issues in 0.9.1 still stands.
- The API still accepts an RM rate request below 13% (the script now never sends one, but
  the RM screen does not stop one). Enforcing the band in the API would be an application
  change and a release of its own.
