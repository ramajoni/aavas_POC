# Release 0.6.2 (2026-11-19)

Previous release: 0.6.1. A patch release of security and integrity fixes, made before
the first deployment of the 0.6 line to AWS. Pricing, the API and the data are unchanged.

## Highlights

- **The AutoGluon Assistant cannot start on the server.** It runs code it writes itself
  with no sandbox, so it is now refused unless a developer explicitly allows it on
  their own machine.
- **Retraining can no longer disturb live pricing.** An agentic run reads its dataset
  without changing anything the rest of the server shares.
- **Promoting a run cannot lose the old champions.** Promotions happen one at a time,
  and the backup of the models they replace is never overwritten.

## Changes

### Security
- The AutoGluon Assistant engine is refused unless
  `training.autogluon_assistant.allow_unsandboxed` is `true` (default `false`,
  `config/agentic_os.yaml` AOS-2026.12). It runs code it writes itself, unsandboxed, as
  the platform user, so it must not start on a shared or production host until it runs
  in an isolated container.

### Fixed
- An AutoGluon Assistant run repointed `AAVAS_RAW_PATH` and `AAVAS_PROCESSED_PATH` in
  the process environment while it read its dataset, so a pricing request served at
  that moment could read the run's data. The loader takes the paths explicitly
  (`load_training_table(raw_path=..., processed_path=...)`).
- Two promotion requests for the same run at once could both pass the "already
  promoted" check, and the second replaced the champions' backup with the models just
  promoted. Promotion now runs under a lock, re-reads the run from disk, and keeps the
  first backup.

## Upgrade steps

None. Leave `allow_unsandboxed: false` on every shared or production host.

## Known issues

- **The AutoGluon Assistant still has no isolation** when it is allowed on a developer
  machine. It receives the platform's AWS credentials, since Bedrock needs them. The
  real fix is a container with Bedrock-only credentials and no other network or host
  access; until then, keep it off servers.
- Everything listed under Known issues in 0.6.1 still stands.
