# Release 0.9.0 (2026-11-21)

Previous release: 0.8.2. A minor release that brings the model tools to the AWS server.
Pricing is unchanged.

## Highlights

- **MLflow and the OmniXAI dashboards work on the cloud.** The browser reaches them through
  CloudFront at `/api/tools/mlflow/` and `/api/tools/omnixai/<port>/`, behind a password, while
  the API still checks them on their local ports. The MLflow and XAI Dashboard pages embed them.
- **The AutoGluon Assistant is found on Linux.** It is installed on the server, and the Agentic OS
  screen says whether it is allowed to run there, instead of "not found".

## Changes

### Added
- The model tools work behind a proxy. MLflow and each OmniXAI dashboard now have a probe
  address, which the API checks from the server, and a public address, which the browser opens
  (`AAVAS_MLFLOW_PUBLIC_URL`; `run_omnixai.py --public-base`, which serves each Dash dashboard
  under `<base>/<port>/`). The MLflow and XAI Dashboard pages link and embed the public address.
  On AWS they are served at `/api/tools/mlflow/` and `/api/tools/omnixai/<port>/`, behind a
  password.
- `AAVAS_MLZERO_CLI` and a single resolver for the AutoGluon Assistant command: the configured
  Windows path (`Scripts/mlzero.exe`) also finds the Linux one (`bin/mlzero`). Readiness reports
  whether it is installed and, separately, whether it is allowed on this host; the Agentic OS
  screen says "installed, but not allowed on this host" instead of "not found".

## Upgrade steps

On a server behind nginx:

1. Run MLflow on localhost with `--static-prefix /api/tools/mlflow`, and set
   `AAVAS_MLFLOW_PUBLIC_URL=/api/tools/mlflow/` and `MLFLOW_TRACKING_URI=file:<shared mlruns>`.
2. Serve the dashboards with
   `run_omnixai.py --public-base /api/tools/omnixai --port-base 8765 --host 127.0.0.1`.
3. Route `/api/tools/mlflow/` (prefix kept) and `^/api/tools/omnixai/(port)/(rest)` (prefix
   stripped) in nginx, behind a password. They sit under `/api/` because that is the CloudFront
   route that allows POST and forwards the Authorization header.
4. Set `AAVAS_MLZERO_CLI` to the installed `bin/mlzero` path.

## Known issues

- **The AutoGluon Assistant cannot run on the server yet.** It needs an IAM role with Bedrock
  access on the server (your admin), Bedrock's Anthropic use-case form (submitted in the
  console), and `allow_unsandboxed` turned on deliberately for that host. It runs model-written
  code with no sandbox.
- **The new area-manager cases are not in this release.** They follow in the next one.
- Everything listed under Known issues in 0.8.2 still stands.
