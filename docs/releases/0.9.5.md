# Release 0.9.5 (2026-11-21)

Previous release: 0.9.4. A patch release of the demo data tools. The application, the policy
(HL-LAP-POLICY-2026.14) and the models are unchanged.

## Highlights

- **The area manager's list, cut to 10 that still show everything.** After 0.9.4 the list
  held 117 requests locally and 134 on AWS, and took over a minute to load. `trim --keep 10`
  keeps ten pending requests that between them cover every grade (A+ to C), every tenure
  band, every ask position (within the room, at the floor, below it), all five kinds of
  competitor evidence, all ten request reasons, all four segments and all ten special
  situations, and removes the rest. On this laptop the list now loads in 3.5 seconds.
- **Safe by default.** Without `--apply` it only prints what it would keep and remove.
  With it, the store is backed up first; the API's request log, the loan book and the audit
  trail are never trimmed, and files that never reached the area manager stay.

## Changes

### Added
- `scripts/demo_catalogue.py trim --keep N`: cut the area manager's approval list to N
  pending requests that between them still show every kind of situation. A deterministic
  coverage search picks them from the requests a store already holds: every grade, tenure
  band, ask position, evidence type, request reason and segment at least once, then the
  special situations (new to credit, balance-transfer threat, month-end target, large
  ticket, LTV, FOIR and age near their limits, late EMIs, a score near 675); the
  hand-written scenarios win ties. A dry run is the default. `--apply` backs up the store,
  then removes every other file that reached the area manager (its rows in every loan table,
  its uploads and its decision-memory entries). The API's request log, the loan book and the
  audit trail are never trimmed, and files that never reached the area manager are left alone.

## Upgrade steps

Nothing to deploy. To trim a server's list (stop the API for the `--apply`, so no decision
is taken while files are removed):

    python scripts/demo_catalogue.py trim --keep 10            # dry run: what would be kept
    python scripts/demo_catalogue.py trim --keep 10 --apply    # back up, then remove the rest

Decision memory is read from its table on every request, so nothing needs rebuilding.

## Known issues

- Everything listed under Known issues in 0.9.4 still stands.
- The approval list computes an analysis for every row on each load (about 0.6 s a
  request), so a long list is slow; trimming hides this rather than fixing it.
