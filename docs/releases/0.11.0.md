# Release 0.11.0 (2026-11-23)

Previous release: 0.10.1. A minor release: two new API endpoints and a new page. The policy
(HL-LAP-POLICY-2026.14) and the models are unchanged.

## Highlights

- **Release notes, inside the application.** Every change to the application is versioned
  and written up; staff can now read those notes where they work. The footer shows the
  running version ("App v0.11.0") beside the policy and model versions, with a small dot
  after an upgrade until it has been opened. The page lists every release since 0.1.0, newest
  first, and opens any one in full.
- **The risk-model work is held back on purpose.** The retrained risk model planned for this
  release corrects two backwards effects but ranks risk a little worse and almost never
  grades a file C. It will ship once it meets the agreed bar, with the one FOIR definition
  and the new Stage-1 quote band, as 0.12.0.

## Changes

### Added
- **Release notes in the application.** Staff (relationship manager, area manager, model
  validation, administrator; never the borrower) open them from the footer, which now shows
  "App v<version>" beside the policy and model versions, with a small "New" dot after an
  upgrade until they have looked. The page lists every release newest first with its date
  and a one-line summary, opens the running release at its highlights, shows any release's
  full notes (tables and nested lists included) and filters by text.
- `GET /releases` and `GET /releases/{version}`, read from `CHANGELOG.md` and
  `docs/releases/`. The version is checked strictly (ASCII digits only) and used only as a
  lookup key; notes are rendered without raw HTML.

### Changed
- `config/access.yaml` ACCESS-2026.12: the Release notes page and route for the staff roles.

## Upgrade steps

Deploy the API and the web application together. Nothing else changes.

## Known issues

- Everything listed under Known issues in 0.10.1 still stands.
