# Release 0.9.1 (2026-11-21)

Previous release: 0.9.0. A patch release of the demo data tool. The application, the
policy (HL-LAP-POLICY-2026.14) and the models are unchanged.

- **Why most asks are below the floor.** Under 2026.14 the engine usually recommends the
  floor itself (card less 60 bps), and the RM may only send an ask more than 25 bps under
  the recommendation. An ask inside the room or exactly at the floor is possible only where
  the recommendation sits more than 25 bps above the floor (E3, E6, E8, E9). Every ask is
  still inside the 13-17% policy band.

## Changes

### Added
- `scripts/demo_scenarios.py --set core|extended|all`. The extended set adds twelve
  area-manager cases that cover the decisions HL-LAP-POLICY-2026.14 allows: grades A+, A, B
  and C; tenures in all three bands (36-60, 61-84, 85-120 months); all four segments;
  verified, unverified and no competitor evidence; a bureau score near the 675 minimum; a new
  to credit applicant sent to manual review; a month-end-target request with no customer
  evidence; a price-insensitive existing customer; tickets near the Rs 75 lakh and 90% LTV
  caps; and asks within the room, exactly at the floor and below it. `core` (the original ten)
  stays the default.
- An `at_floor` ask kind (asks exactly the policy floor). Each created request now prints its
  card, floor, recommendation, ask and where the ask sits (within room, at floor, below floor).

### Fixed
- `scripts/demo_scenarios.py` always sent `new_to_credit: false`. A scenario without a bureau
  score (a score below zero) is now sent as new to credit.

## Upgrade steps

Nothing to deploy: the running application is unchanged. To add the cases to a server
that already has the core set:

    python scripts/demo_scenarios.py --base http://127.0.0.1:8000 --set extended

`--set all` creates both sets on an empty store (after `scripts/demo_reset.py`). The script
backdates each file through the store named by `AAVAS_STORE_URL`; when that is not the
server's store, set it or pass `--no-backdate`.

## Known issues

- No loan-against-property case: the pre-assessment API accepts only the four housing
  property types (resale flat, builder flat, self-construction, plot plus construction).
- No D-grade case (declined before it reaches the area manager) and no ask beyond the area
  manager's 100 bps authority (the policy floor always binds first).
- The grades and recommendations above were found by probing the current model and policy.
  If either changes, some files may land in a different grade or position.
- Everything listed under Known issues in 0.9.0 still stands.
