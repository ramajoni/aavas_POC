# Release 0.8.0 (2026-11-20)

Previous release: 0.7.1. A minor release of two features for the area manager. Pricing and
the policy are unchanged: neither feature can move a rate.

## Highlights

- **Decision memory.** Each time an area manager decides a lower-rate request, the decision is
  kept as an episode. It records the factors as the manager saw them, the suggestion shown, the
  decision, the rate and the note. When they open the next request, the manager memory agent
  recalls their own and other managers' most similar past decisions and what each customer
  then did. It shows how this manager tends to decide, and where today's suggestion differs
  from that.
- **Milvus precedent search.** "Most similar past negotiations" finds the eight past notes
  closest in meaning to the file under review: the same competitor letter, the same kind of
  objection. Each comes with its outcome. It runs on Milvus (embedded Milvus Lite) with a local
  embedding model, so no data leaves the server.
- **Both are context for a person.** The decision is still the manager's, and memory or
  precedents never change the suggestion or the price (tests assert both).

## Changes

### Added
- **Decision memory for the area manager.** Every decision on a lower-rate request is
  remembered as an episode: the fifteen factors with their signals as the manager saw them,
  the suggestion shown, the decision, the rate and the note, and which past cases were
  recalled at the time. The learning agent writes it (still the only agent that writes the
  governance store); the episode is never edited, and what the customer did is joined when
  memory is read.
- **Manager memory agent** (on request, outside the priced path). When an area manager opens a
  request it recalls their own most similar past decisions and other managers', each with
  why it is alike and what the customer did; how this manager tends to decide (cut, hold or
  price higher, how often they take the suggestion, which factors move them, as counts); and
  whether today's suggestion differs from their usual decision. It never moves the suggestion.
- `GET /pricing/rate-requests/{request_id}/memory`; `POST .../decide` returns `memory`.
- A "Your decision memory" panel on the decision-support screen. The screen's factor signals
  now come from the server (`analytics/decision_factors.py`), so the screen and memory read one
  set of rules.
- The `decision_memory` table. The memory registry in the system of record is now a registry,
  not absent.
- **Milvus for the area manager's precedents.** A Milvus vector store (Milvus Lite, embedded,
  one file on the server) with local BAAI bge-small-en-v1.5 embeddings via fastembed. When a
  manager reviews a lower-rate request, "Most similar past negotiations" lists the eight past
  notes closest in meaning to this file's conversation, competitor and reason, same city
  first, with what happened in each (took the loan or not, at what rate, priced up or down).
  Context for a person only: it never changes a price.
- `GET /pricing/rate-requests/{request_id}/precedents`; `/history` returns `similar_negotiations`.
- `AAVAS_VECTOR_BACKEND=milvus` (with `AAVAS_MILVUS_URI`, `AAVAS_EMBED_CACHE`) turns it on; the
  index is rebuilt only when the notes change. Milvus Lite has no Windows build, so there, or if
  Milvus fails, the app falls back to the in-memory TF-IDF search and says which one answered.
- The embedding model is in the model-risk inventory (`embedding_bge_small`, MRM-2026.12) as a
  third-party model with a kill switch and the TF-IDF fallback.
- `pymilvus` and `fastembed` in `requirements-optional.txt`.

## Upgrade steps

1. `pip install -r requirements.txt -r requirements-optional.txt` (adds `pymilvus`,
   `milvus-lite` on Linux and macOS, and `fastembed`). pymilvus 3.x no longer installs Milvus
   Lite itself, so it is listed separately.
2. Set `AAVAS_VECTOR_BACKEND=milvus`, `AAVAS_MILVUS_URI=<file on persistent disk>` and
   `AAVAS_EMBED_CACHE=<writable folder>`. The first start downloads the embedding model (about
   65 MB) once.
3. Build the index once before users arrive. Embedding the notes takes minutes on CPU; later
   starts reuse it while the notes are unchanged.
4. The `decision_memory` table is created on start. No migration is needed.
5. To switch Milvus off, set `AAVAS_VECTOR_BACKEND=memory`; the app goes back to TF-IDF search.

## Known issues

- **No Milvus on Windows.** Milvus Lite has no Windows build, so Windows machines use the TF-IDF
  fallback; the screen says which search answered.
- **Policy questions change scoring under Milvus.** With Milvus on, "Ask a policy question"
  also searches by embeddings (cosine similarity) instead of TF-IDF. Answers may be ranked
  differently.
- **Slower test suite.** The full suite now takes about 19 minutes on a laptop, against about 3
  before, because the area manager's request views build the notes index. In production the
  index is built once per corpus.
- Everything listed under Known issues in 0.7.1 still stands.
