# Release 0.9.6 (2026-11-21)

Previous release: 0.9.5. A patch release of the demo data tools. The application, the policy
(HL-LAP-POLICY-2026.14) and the models are unchanged.

## Highlights

- **Every special situation in the 10.** On AWS the 0.9.5 pick covered every grade, band,
  ask position, evidence type, reason and segment, but left out the new-to-credit case. A
  swap pass after the greedy pick now trades a kept request for one left out whenever that
  covers more, so the 10 show every situation the store holds.
- **Upload folders are removed only inside the upload root.** A stored loan id is treated
  as data: unless it is a plain loan id that resolves directly under the upload root, its
  folder is skipped and reported.

## Changes

### Fixed
- `trim` could leave a special situation out of the 10 (on AWS it missed the new-to-credit
  case) because the greedy pick spent a slot on a grade-and-band pair. A swap pass now
  exchanges a kept request for one left out whenever that covers more single values (every
  grade, band, ask position, evidence type, reason, segment and special situation), and only
  then more weighted pairs.

### Security
- `trim` removed each file's upload folder at `upload_dir()/<loan_id>` with the id read from
  the store. An id such as `../x` stored through an endpoint that only checks its length could
  have pointed outside the upload root. The folder is now removed only when the id is a plain
  loan id (`^[A-Za-z0-9-]{3,40}$`) that resolves directly under the upload root; anything
  else is skipped and reported.

## Upgrade steps

Nothing to deploy. Run `trim --keep 10` (dry run) and then `--apply` as in 0.9.5.

## Known issues

- Everything listed under Known issues in 0.9.5 still stands.
- The pricing and rate-request APIs check a loan id's length but not its form; tightening
  them is planned for 0.10.0.
