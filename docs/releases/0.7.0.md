# Release 0.7.0 (2026-11-19)

Previous release: 0.6.4. A minor release. It adds a reusable policy kit; pricing, the
API and the data are unchanged.

## Highlights

- **Any lender can now reuse the policy structure.** `policy_kit/` describes the common
  structure of the pricing policy. Another company fills in its own values (rates,
  grades, segments, limits, approval levels) and runs the result in this engine.
- **Every section is explained.** There are 44 sections in six parts. Each is marked as
  required by the engine (19), optional (22) or jurisdiction-specific (3, for India and
  RBI rules), with an owner and a plain description of what it controls.
- **A filled policy can be checked before it is used.**
  `python scripts/policy_kit.py validate <file>` checks it against the schema and runs
  the engine's 83 consistency checks. It lists every value not yet filled in and every
  rule broken. The live policy passes all of them; the blank template fails, as it
  should.

## Changes

### Added
- A reusable lending policy kit (`policy_kit/`): the common structure of a pricing
  policy that any lender can fill in and run in this engine. It holds 44 sections in six
  parts (governance; pricing; credit and eligibility; authority and overrides; controls;
  decision record), each marked as required by the engine, optional or
  jurisdiction-specific, with an owner and a plain purpose. It ships a blank template, a
  JSON Schema and an adoption guide.
- `scripts/policy_kit.py`: `build` regenerates the schema, the template and the README
  table from the live policy, so the kit keeps step as the policy changes; `validate`
  checks any company's policy against the schema and the engine's own consistency
  checks, naming every value not yet filled in.
- `jsonschema` in `requirements.txt`, for the validator.

## Upgrade steps

1. `pip install -r requirements.txt` (adds `jsonschema`).
2. To adopt the kit at another company:
   1. Copy `policy_kit/lending_policy.template.yaml`.
   2. Fill in every placeholder.
   3. Run `python scripts/policy_kit.py validate <file>` until it passes.
   4. Install the file as `config/pricing_policy.yaml`.
   `policy_kit/README.md` walks through each step.
3. After changing the live policy, run `python scripts/policy_kit.py build`. It
   refreshes the kit, and a test fails if the committed kit has drifted from the policy.

## Known issues

- Which parts of the policy the engine reads was found by scanning the code, not by
  tracing a run. Fifteen sections are documentation only; the engine does not read
  them, and the kit says so.
- Everything listed under Known issues in 0.6.4 still stands.
