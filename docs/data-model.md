# Data model and configuration

Every dataset, table, artefact and configuration knob in the system, and which module owns it.

---

## 1. The lifecycle table

One row per application, one `loan_id` threading the whole journey. Declared in
[`ingestion/schemas.py`](../src/aavas/ingestion/schemas.py); generated by
[`synthetic/generator.py`](../src/aavas/synthetic/generator.py); assembled by
[`ingestion/loader.py`](../src/aavas/ingestion/loader.py).

```
enquiry → stage1 band → assessment → stage2 recommendation
        → human decision → sanction → disbursal → behaviour → yield
```

The price columns, in the order they occur (`LIFECYCLE_ORDER`):

| Column | Meaning |
|---|---|
| `policy_card_rate` | What the grid allows |
| `ai_recommended_rate` | What the engine recommended |
| `sales_offered_rate` | What the human offered |
| `sanctioned_rate` | What credit sanctioned |
| `realized_yield_pct` | What the book actually earned |

### Column groups

| Group | Columns |
|---|---|
| **Identity** | `loan_id`, `application_date`, `state`, `city`, `branch_id`, `sales_officer_id` |
| **Pre-assessment** | `segment`, `channel`, `property_type`, `applicant_age`, `declared_monthly_income`, `new_to_credit`, `bureau_score`, `declared_obligations`, `requested_loan_amount`, `estimated_property_value`, `estimated_ltv`, `requested_tenure_years` |
| **Post-assessment** | `verified_monthly_income`, `income_verification_haircut`, `bureau_vintage_months`, `delinquency_count_24m`, `banking_behaviour_score`, `appraised_property_value`, `tenure_years`, `sanctioned_loan_amount`, `ltv`, `deviation_count`, `legal_flag`, `technical_flag`, `foir`, `risk_grade` |
| **Sales context** | `competitor_rate`, `competitor_name`, `competitor_evidence_verified`, `days_to_month_end`, `month_end`, `sales_target_pct`, `branch_target_pct`, `existing_relationship`, `prior_negotiation_rounds`, `customer_negotiating` |
| **Decision** | `policy_card_rate`, `ai_recommended_rate`, `override_bps`, `override_reason`, `sales_offered_rate`, `sanctioned_rate`, `credit_clawback` |
| **Outcome** | `customer_response`, `disbursed`, `bt_out_24m`, `delinquent_12m`, `defaulted`, `months_to_exit`, `realized_life_years`, `realized_yield_pct`, `realized_value_pct`, `realized_value_inr` |
| **Latent (synthetic only)** | `true_pd`, `true_lgd`, `price_elasticity`, `true_conversion_probability`, `true_bt_probability` |
| Also | `stage1_min_rate`, `stage1_max_rate`, `sanctioned` |

> **`LATENT_COLUMNS` are ground truth that exists only because the data is synthetic. They are
> never features.** They exist so the POC can ask questions real data cannot answer — e.g.
> whether the conversion model recovers the latent elasticity (rank correlation ≈ 0.47).

### Derived columns

Added by `loader.add_derived_columns()` and shared across models:

| Column | Definition | Why |
|---|---|---|
| `offered_rate` | `= sanctioned_rate` | Conversion and prepayment are trained on **the rate the customer was actually shown**, which is what makes them scoreable at a hypothetical price |
| `competitor_gap_bps` | `(sanctioned_rate − competitor_rate) × 100` | The competitive position the customer saw |
| `recommended_gap_bps` | `(ai_recommended_rate − competitor_rate) × 100` | The engine's position |
| `was_overridden` | `override_bps ≠ 0` | Treatment flag for override learning |
| `override_direction` | `discount` / `none` / `premium` | |
| `total_discount_bps` | `(policy_card_rate − sanctioned_rate) × 100` | Total leakage from card |
| `application_month` | Period from `application_date` | Cohort slicing |

### Validation

[`ingestion/validator.py`](../src/aavas/ingestion/validator.py) runs on every build:
type coercion, range and consistency checks, quarantine of impossible rows (they are written
aside, not silently dropped), and `assert_no_leakage(feature_columns, stage)` which refuses a
Stage-1 feature list containing post-assessment columns.

Policy-breaching files are already removed by the generator as "declined at credit", so every
surviving row is policy-consistent — a rule that caught 958 impossible rows during development.

### Splitting

`loader.train_test_split(strategy="time")` — chronological 80/20 on `application_date`.
Pricing is non-stationary; a random split flatters the model.

## 2. Feature contracts

[`config/feature_config.yaml`](../config/feature_config.yaml), version `FEAT-2026.09`. One block
per model, each with `numeric`, `categorical` and optional `monotone` maps.

| Contract | Notable inclusions / exclusions |
|---|---|
| `stage1` | Declared figures, soft-pull bureau, `estimated_ltv`, competitor and target context. **No verified/assessed field may appear here.** |
| `stage2` | Verified income and haircut, appraised value, `ltv`, `foir`, bureau depth, deviations, legal/technical, plus sales context |
| `risk` | Deliberately **not** the `stage2` block: `risk_grade` is derived from this model's own output, so including it would be circular |
| `conversion` | Includes `offered_rate` and `competitor_gap_bps`, both monotone non-increasing |
| `prepayment` | `offered_rate` monotone non-decreasing |
| `override` | Sales-context-heavy: the model predicts human behaviour, not credit |
| `sales_context` | The block `reason_codes.commercial_share()` uses to split commercial from risk attribution |

The same file also holds `reason_code_labels`: the human-readable label and up/down phrasing
per feature that turns a raw attribution into a sentence a branch can use ("Weaker risk grade",
"Competitive market pressure"). Changing the wording a customer sees is a config edit.

Monotone constraints are declared here and travel into the learner via
`FeatureSpec.monotone_vector()` — never hard-coded in a training script. Categoricals are
ordinal-encoded (all learners are tree-based) with an explicit `__unknown__` bucket, so an
unseen category scores instead of crashing.

## 3. Governance store schema

SQLite by default (`aavas_governance.db`); `AAVAS_STORE_URL` points elsewhere.
Defined in [`governance/store.py`](../src/aavas/governance/store.py).

| Table | Key | Write pattern | Contents |
|---|---|---|---|
| `decisions` | `decision_id` | append-only | `loan_id`, `stage`, `created_at`, `recommended_rate`, `card_rate`, `min_rate`, `max_rate`, `conversion_probability`, `expected_value_inr`, `required_approval`, `policy_version`, `model_versions`, `elapsed_ms`, full `payload` |
| `overrides` | `override_id` | one per captured decision | `decision_id`, `loan_id`, `ai_rate`, `human_rate`, `override_bps`, `reason`, `reason_detail`, `evidence_verified`, `approved_by`, `required_approval`, `within_authority`, `sales_context`, `payload` |
| `outcomes` | `loan_id` | upsert as the file matures | `customer_response`, `disbursed`, `sanctioned_rate`, `bt_out`, `delinquent`, `months_to_exit`, `realized_yield_pct`, `realized_value_pct`, `payload` |
| `audit_log` | autoincrement | append-only | `created_at`, `actor`, `action`, `entity_type`, `entity_id`, `detail` |
| `model_registry` | (`name`, `version`) | role updated on promotion | `role` (`champion` / `challenger` / `retired`), `registered_at`, `card` |

Indexes: `decisions(loan_id)`, `decisions(created_at)`, `overrides(loan_id)`,
`audit_log(entity_type, entity_id)`.

Dict/list values are JSON-encoded on write and decoded by `store.decode()`. `store.reset()`
drops and recreates everything — tests and demos only.

Audit actions written by the engine include `capture_override`, `capture_outcome`,
`fair_pricing_review_required`, `retrain_model`, `promote_model` and `promote_challenger`.

## 4. Model artefacts

`models/<name>__<version>.joblib` — a dict of `{"payload": ..., "card": ...}` where the payload
carries the fitted estimator(s) **and** the fitted `FeatureTransformer`, plus model-specific
extras (`quantiles` for stage1, `residual_std` for stage2, the conversion model's `support`
band, the prepayment `horizon_months`, the risk grade cut-offs and LGD table).

`models/<name>__<version>.card.json` — the same card as a readable sidecar:

| Card field | Content |
|---|---|
| `name`, `version`, `learner`, `target` | Identity |
| `trained_at`, `n_train`, `n_test`, `training_window` | Provenance (`from`/`to` dates of the training data) |
| `features` | The exact column list fitted |
| `metrics` | Holdout metrics (see below) |
| `config_versions` | app / policy / feature-config / model-config versions in force |
| `limitations` | Written list of what the model cannot be trusted to do |

Current artefacts (20,000 synthetic applications, chronological 80/20):

| Model | n_train / n_test | Key metrics |
|---|---|---|
| `stage1` | 16,000 / 4,000 | coverage 80.4%, mean width 74.4 bps, median MAE 23.1 bps, inverted bands 0 |
| `stage2` | 16,000 / 4,000 | MAE 11.7 bps, RMSE 15.1 bps, R² 0.984, within 25 bps 90.3%, residual σ 12.8 bps |
| `conversion` | 16,000 / 4,000 | AUC 0.700, Brier 0.199, calibration gap 0.002, −9.6 pts per +25 bps, monotonicity violations 0% |
| `prepayment` | 10,544 / 2,637 | AUC 0.643, base rate 15.3%, horizon 24 months |
| `risk` | 10,544 / 2,637 | AUC 0.697, Brier 0.080, base rate 9.4% |
| `override` | 16,000 / 4,000 | AUC 0.682, magnitude MAE 9.7 bps (n=1,450) |

Prepayment and risk train on **disbursed** files only, which is why their row counts are lower —
and why their cards carry a selection-bias limitation.

## 5. Configuration reference

All four files live in [`config/`](../config/) and are read through
[`config.py`](../src/aavas/config.py) (cached; `reload()` clears). **Nothing in `src` may
hard-code a rate, spread, cost or threshold a business user would reasonably want to change.**

### `pricing_policy.yaml` — business-owned (`HL-POLICY-2026.10`)

| Block | Drives |
|---|---|
| `reference` | `plr`, `card_rate_floor` (8.60), `card_rate_ceiling` (16.50) |
| `economics` | Funding 7.90%, servicing 0.45%, acquisition 0.55%, processing fee 0.50%, capital 0.35%, discount rate 9.00%, `behavioural_horizon_years` 8 — every rupee in the yield calculator |
| `base_spread_bps` | Segment spread over the floor (55 → 185 bps) |
| `risk_grade_loading_bps` | A 0 → E 240 bps |
| `ltv_loading_bps`, `property_type_loading_bps`, `deviation_loading_bps` | The rest of the card rate |
| `constraints` | `max_ltv` 0.90, `max_foir` 0.55, `max_tenure_years` 30, `min_credit_score` 620, NTC rules, `max_loan_amount`, `absolute_discount_floor_bps` 60 |
| `approval_authority` | Level → max discount / max premium bps (sales officer 10 → pricing committee 999) |
| `override` | `allowed_reasons` (10), `evidence_required_reasons`, `max_unevidenced_discount_bps` 15 |
| `stage1` | Quantiles, `min/max_band_width_bps` (25/125), `round_to_bps` 5, `eligibility_foir_cap` 0.50 |
| `fair_pricing` | `commercial_uplift_review_bps` 10, `quote_validity_days` 30, risk-grade scale wording |
| `optimizer` | `step_bps` 5, `search_space` (`permissible_band` \| `stage2_interval`), `min_conversion_probability` 0.25, `max_bt_out_probability` 0.45, `ev_tolerance_pct` 1.0 |

### `model_config.yaml` — ML-owned (`MODEL-2026.09`)

`seed` 42 · `data` (20,000 rows, paths, `test_size` 0.2, time split) · `registry` (dir,
version) · `tracking` (MLflow, off) · per-model learner and params · `risk.pd_horizon_years`
4.0 and grade cut-offs · `xai` (backend auto, top-5 reason codes, 2 bps noise floor) ·
`drift` (PSI warn 0.10 / alert 0.25, `performance_window` 500) · `champion_challenger`
(`shadow_min_decisions` 300, `promote_if_better_by_pct` 2.0, `max_conversion_drop_pct` 1.0,
`require_human_signoff` true).

### `feature_config.yaml` — see [§2](#2-feature-contracts).

### `federated_config.yaml` — phase 2 (`FED-2026.09`, `enabled: false`)

`partition_key: state` over five regions · `strategy` (fedavg / weighted / uniform /
trimmed_mean / fedprox) · `rounds` 30, `local_epochs` 5 · `holdout_fraction` 0.25
(personalization must be judged out of sample) · `min_rows_per_client` 300 — a thin region
does not get to move the global model · `personalization.alpha` 0.6 with `adaptive_alpha`
(thin regions lean global) · `privacy` placeholders for secure aggregation and DP noise ·
`federated_target: regional_rate_adjustment` — only the parametric regional adjustment is
federated; the central GBMs stay centrally trained.

## 7. Units and conventions

* Rates are **annual percentages** (`12.79` = 12.79% p.a.).
* Spreads, loadings, deltas and tolerances are **basis points**.
* Money is **INR**; `expected_value_inr` is per file.
* Probabilities are in `[0, 1]`; "points" in text means **percentage points** of conversion.
* `risk.pd` is **annualised**; `risk.lifetime_pd` is the raw model output over
  `pd_horizon_years`. Confusing the two inflates expected loss ~4× and grades every file D/E.
* `expected_loss_pct` is annual, so it can be subtracted from an annual spread.
